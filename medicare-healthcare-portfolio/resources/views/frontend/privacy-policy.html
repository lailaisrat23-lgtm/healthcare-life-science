Privacy policy (sample document)

This is a sample policy written for a portfolio demonstration. It is not legal advice and would require review by a qualified professional before any real healthcare service used it.

Sample text — requires legal review

Nothing on this page reflects a real data-processing arrangement. It illustrates the sections a healthcare platform policy would typically contain.

1. Purpose of this document

This sample policy describes how a static portfolio demonstration would handle information, and it documents the deliberate absence of data collection. The project stores no backend data, uses no database, and performs no server-side processing of any kind.

2. Information handled by this demonstration

The demonstration does not collect personal information. Form fields exist for interface purposes only: values are read in the browser to produce validation and confirmation messages, and are then discarded. Specifically, this project does not:

  • transmit form values to any server, clinic, laboratory, pharmacy or supplier;
  • persist form values in cookies, local storage, session storage or IndexedDB;
  • collect analytics, telemetry, advertising identifiers or device fingerprints;
  • request, store or display patient-identifiable information of any kind.

3. Intended data use in a production system

A real implementation would need to describe the lawful basis for processing, the specific purposes of each collection point, minimum-necessary data rules, and retention periods per data class. This demonstration deliberately contains no such processing so that no such obligations arise.

4. Cookies and similar technologies

This project sets no cookies and uses no client-side storage. If a production version added analytics or personalisation, a consent mechanism and a cookie table would be required before deployment.

5. Third-party services

No third-party service, CDN, font host, analytics provider or API is called at runtime. All images are locally authored SVG files, and all data is bundled with the project.

6. Security

Because no data is transmitted or stored, there is no data at rest or in transit to protect. A production equivalent would need transport encryption, access control, audit logging, encryption at rest, key management and incident response procedures.

7. Data retention

Nothing is retained. Closing or reloading a page discards everything entered into the demonstration forms.

8. Your rights

Data-subject rights such as access, correction, deletion, restriction, portability and objection apply to real personal data. Since this demonstration processes none, there is no personal data to access, correct or erase. Requests about a real service would need a documented response process.

9. Children's privacy

The demonstration is not directed at children and collects no information from any visitor.

10. Changes to this sample

This sample may be updated as the demonstration evolves. Any production policy would need versioning, effective dates and a notification mechanism.

11. Contact

Demonstration contact details are placeholders. See the contact page for the fictional addresses used in this project.
